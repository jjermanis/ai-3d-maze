version 1	40 minutes dev	4 minutes code gen	6 minutes test		50 minutes total

The goal is to go with a simple maze playing game. The point-of-view would be a standard 2D view,
like you would see on a piece of paper. The game would use Depth First Search to create the map
on a 20x20 grid. It would use a gray arrow as the player to move through the map. It would use
the arrow keys: left and right to turn, and up to go forward (if not blocked). The initial 
version looked nice, but had two bugs. One was the not all of the path was reachable. It was 
almost all of it, maybe 98%. But it should be all. The other was that the arrow spun correctly.
But moving forward? That was messed up. It would go if a different direction than expected, not
in a predictable way. I focused on the directions. I tried several ways to adjust moving forward.
I added debug info. It was confusing because the log matched the behavior, but did not line up
to the code. 
I tried generating again from scratch, with two small changes. One I made it a point to say "The 
tip of the arrow points forward." I also added the sentence "Every square in the maze should be
reachable." This worked! Both previous defects were resolved with these changes. The game is 
playable as-is. Playable... but not the end goal.
Since this game was regenerated from scratch, the UI looks different, and unfortunately worse.
The game works, but there are several things to fix before moving on.


version 2 	24 minutes dev	4 minutes code gen	6 minutes test		1 hour 24

There were a lot of refinements to make. Before getting into that, I wanted to get the remaining
core feature: adding a 3D point of view. The UI switched to two displays. On the right is the same 
2D maze as in the original. On the left, a 3D point-of-view from where the 2D player is. The first
attempt looked surprisingly good. Looked good; movement was rough. Two major issues seen. 
One, the character could walk through walls. Not all walls, but some. And sometimes block 
by space.
Two, the character moving forward was off - it went a different direction than it pointed. 
I described both of the issues in detail and provided them to Chat. It fixed... one of them.
It now checked the walls correctly. There were still issues moving forward, off by a 90 degree
angle. I described that to Chat. It fixed it with a one-liner... but added a bug to the 3D view. 
The 3D view became off by 90 degrees. I described that to Chat. It fixed that with a one-liner. 
It all works now! Actually playable! Many thing to add, but a nice start for sure. I am impressed 
with what it developed in limited time.


version 3	17 minutes dev	2 minutes code gen	4 minutes test		1 hour 47

This adds what I think is the biggest function for this initial version. To start, the 2D
map shows the entire map. I want squares to appear only once they are seen directly as the
arrow walks around the maze. This game VERY close to working on the first attempt. Things
started gray, and showed the map when seen on the 3D view. But it is a little too clearly
up: it seems to allow include 1 pixel behind the last wall. My theory was that when checking
for how far a user can see on the 3D screen, would keep going until it crossed a wall. It 
would add all of those to the 2D INCLUDING the last one past the wall. I wrote this up to
Chat. It agree, and rewrote to check that a wall has been passed before asking then to be
seen. This appeara perfect - it behaves as I expected. This, for sure, is a playable game.
I will proceed with polishing up some UI before publishing Release #1.


Version 4	32 minutes dev	4 minutes code gen	5 minutes test		2 hours 28
DID NOT PROCEED - RETURNING TO VERSION 3 ON NEXT ATTEMPT

The game was working nicely, but the UI was rather abstract. Walls were basic red walls.
I tried to add brick walls. Not just red bricks - bricks covered in mortar. I asked Chat
to create this. It REALLY did not work. The code to show the vertical lines was severly
bugged - it basically made the wall white, almost all mortar. If I removed the vertical
lines, it would work... to an extent. Mortar straight ahead looks decent. On the side
walls, they did not lined up well. I reported defects to Chat. 
It recognized what I reported, and suggested using only horizontal mortar. I
did not like the idea but I tried it. It was worse: after that change, the horizontal lines
bent as you got close. I pointed this out and asked for a different solution all together.
It did suggest a different approach. It had been a ray-per-column renderer. It redesigned
to a texture-mapped wall. There were quite a few changes; I applied them. It worked, but
added a whole new defect: vertical gaps in all walls. This looked odd in general and for
a wall on the edge, it was clear: you could repeatedly see outside through the gaps. This 
did not work. Maybe there was a marginal change, but it was not fixed.
I decided to back down from this approach. Next I will try an entirely different way to
add detail to the walls.
