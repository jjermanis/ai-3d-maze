version 1	40 minutes dev	4 minutes code gen	6 minutes test		50 minutes total

The goal is to go with a simple maze playing game. The point-of-view would be a standard 2D view,
like you would see on a piece of paper. The game would use Depth First Search to create the map
on a 20x20 grid. It would use a gray arrow as the player to move through the map. It would use
the arrow keys: left and right to turn, and up to go forward (if not blocked). The initial 
version looked nice, but had two bugs. One was the not all of the path was reachable. It was 
almost all of it, maybe 98%. But it should be all. The other was that the arrow spun correctly.
But moving forward? That was messed up. It would go if a different direction than expected, not
in a predictable way. I focused on the directions. I tried several ways to adjust moving forward.
I added debug info. It was confusing because the log matched the behavior, but did not line up
to the code. 
I tried generating again from scratch, with two small changes. One I made it a point to say "The 
tip of the arrow points forward." I also added the sentence "Every square in the maze should be
reachable." This worked! Both previous defects were resolved with these changes. The game is 
playable as-is. Playable... but not the end goal.
Since this game was regenerated from scratch, the UI looks different, and unfortunately worse.
The game works, but there are several things to fix before moving on.

Version 11	31 minutes dev	3 minutes code gen	4 minutes test		6 hours 20

I wanted to add a drop-down menu that allows the user to change the size of the maze.
This was reasonably complicated to specify. This is a brief version of what I specified:
I want to add a drop-down menu, above the upper-right corner of the 2D view. 
This dropdown changes the number of cells in the maze. There are two global 
variables that exist. SIZE is the number of cells on both the X and Y axis. 
CELL is the number of pixels used in the 2D view. Right now, there are const 
There will be an array of the SIZE values. These will be [10, 16, 20]. There 
will be an array of the CELL values. These will be [40, 25, 20]. When the 
dropdown menu selection is made and changes, it is like doing a reset: it 
changes the size of the variables and resets the game.
The first step that Chat provide was placing the dropdown menu. That had a bug: the drop-down
and 2D were placed next to the 3D. This made the 2D smaller. I corrected it by realigning
moving the drop-down above the maze view - this is similar to what is done with the reset
button.
The next step Chat provided was to set the data for a size selection change. This was simple
and correct. It didn't actually make the change, but it set the data correctly.
The final step Chat provided was to enable the data change. It make a fairly extensive set
of code changes. This was extraneous - all it needed was to call the initGame() button. That
was done, and it worked!
There was a small edge case. If you open the drop-down, and either don't pick and item and 
close it, or you pick the same item (no change), the drop-down menu retains focus. After that
when you play the game on your keyboard, since the drop-down had focus, attempt to move the
arrow would instead change the size. A couple attempts were made to fix this. Neither worked:
one made it worse, one still had the same defect. Since this is an edge case, for now I will
commit with this defect. You can workaround by clicking outside the drop-down menu. This is
not fun, but it works. I will try to resolve later.
